# AI Command Runner

外部AI（Claude Code、Claude Desktop など、ローカルファイルシステムを直接読み書きできるAI）と協働開発するためのVSCode拡張機能です。

以下の2つを解決します。

1. **AIが提示したコマンドの実行** — コピーしてターミナルに貼る手作業をなくし、サイドバーのボタンで完結させる
2. **プロジェクト固有コマンドの管理** — よく使うコマンドを登録し、ピン留め・常駐・順次実行できるようにする

いずれも実行結果は構造化ログとしてプロジェクト内に書き出されるため、**AIがログを直接読んで次の判断ができます**。

## 仕組み

```
外部AI
   │ ① リクエストを書き込む
   ▼
.vscode/ai-runner/requests/<requestId>.json
   │ ② 拡張機能が検知し、サイドバーにボタンを生成
   ▼
   │ ③ ユーザーがコマンド全文を見て承認・実行
   ▼
.vscode/ai-runner/logs/<requestId>.json  ← 概況（status, exitCode, 末尾50行）
.vscode/ai-runner/logs/<requestId>.log   ← 出力全文
   │ ④ AIが直接読む
   ▼
外部AIが結果を踏まえて次の指示を生成
```

AIに読ませる仕様は、コマンドパレットの **「AI Runner: ワークスペースを初期化」** を実行すると `.vscode/ai-runner/README.md` に書き出されます。AIにはこのファイルを読ませてください。

## セキュリティ設計

この拡張機能は**任意コマンドを実行する仕組み**であり、その入口となる `requests/` にはAIだけでなく、リポジトリを取得した第三者もファイルを置けます。そのため以下を設計上の前提としています。

- **自動実行しない。** 実行の起点は常にユーザーのクリックです。リクエストを検知しても、勝手に実行する経路は存在しません
- **コマンド全文を必ず表示する。** ラベルだけを見せて中身を隠しません。`label` に嘘が書かれていても、実行されるコマンドはUI上で確認できます
- **既定で確認ダイアログを出す。** `aiRunner.requests.confirm` で無効化できますが、既定は有効です
- **信頼されたワークスペースでのみ動作する。** VSCodeのWorkspace Trustに対応しています
- **`cwd` はワークスペース内に限定される。** 外を指すリクエストは実行前に拒否されます

コマンドは `shell: true` で実行されます。パイプや `&&` が使える利便性と引き換えに、シェルの解釈を経る点は理解した上でお使いください。

## 操作

サイドバーは3つのビューで構成されます。

| ビュー | 内容 |
|---|---|
| 承認待ち | AIが書いたリクエストの承認待ち一覧 |
| コマンド | `commands.json` に登録したコマンド |
| 履歴 | 実行結果を新しい順に表示。クリックでその実行のログが開く |

| 操作 | 動作 |
|---|---|
| 項目をクリック | ログを開く（実行中ならそのログ、停止中なら最後の実行ログ） |
| ▶ ボタン | 実行 |
| ■ ボタン | 停止 |

実行はボタンに限定しています。一覧を眺めているだけのつもりが誤クリックで実行される事故を防ぐためです。承認前のAIリクエストだけは例外で、クリックすると整形された詳細パネル（Webview）が開きます。生の `requests/*.json` は見せず、種別・作業ディレクトリ・実行されるコマンド全文を読みやすく表示し、その場で「実行を承認」「拒否」ができます。

詳細パネルに表示する内容は外部AIが書いた未検証の文字列なので、HTMLへ差し込む際に全てエスケープし、CSPとnonceで自前スクリプト以外の実行を禁止しています（XSS対策）。

ログは実ファイルではなく読み取り専用の仮想ドキュメントとして開きます。実ファイルを直接開くと、エクスプローラーが `logs/` を自動展開して大量のログで埋まってしまう（`explorer.autoReveal` の挙動）ためです。AIが読むのは従来どおり `logs/` の実ファイルなので、そちらは変わりません。手元で `grep` したい場合などは実ファイルを開いてください。

実行中の項目には `実行中 2:31 · 最終出力 3秒前` のように、経過時間と最後にプロセスが何か出力してからの時間が出ます。スピナーだけでは生きているのか固まっているのか分からないためです。ただし常駐コマンドは正常でも無出力が続くため、**無出力は異常の証拠にはなりません**。あくまで判断材料です。

## プロセスの停止について

`shell: true` で `npm run dev` を起動すると、実際に動くのは `sh` → `npm` → `node` という孫プロセスです。そのため子プロセスを殺すだけでは孫が生き残り、**停止したはずなのにポートが解放されない**状態になります。

これを避けるため、子プロセスは `detached: true` で新しいプロセスグループのリーダーとして起動し、停止時は `process.kill(-pid)` でグループ全体にシグナルを送ります。SIGTERMを送り、猶予時間内に終わらなければSIGKILLに切り替えます。

VSCode終了時には `deactivate()` で全プロセスを停止し、**終了を待ってから**拡張ホストを終わらせます。待たずに終了すると、シグナルが届く前に拡張ホストが消えてプロセスが取り残されます。VSCodeが `deactivate()` を待つ時間には限りがあるため、予算（既定3秒）を超えた場合は打ち切りますが、SIGKILLは送出済みなのでプロセスは遅れて終了します。

ただし拡張ホストがクラッシュした場合や `kill -9` された場合は `deactivate()` 自体が呼ばれないため、プロセスが残ります。これはVSCode拡張の構造上避けられません（`detached` の有無に関わらず、unixでは親が死んでも子は死なずinitに引き取られます）。

## 機能

| 機能 | 説明 |
|---|---|
| AIリクエストの実行 | `requests/` を監視し、承認待ちとしてサイドバーに表示 |
| リクエストの拒否 | 理由を添えて拒否できる。拒否も `status: "rejected"` としてログに残るため、AIが結果を待ち続けない |
| コマンド管理 | `commands.json` に登録したコマンドをワンクリック実行 |
| ピン留め | よく使うコマンドを上部に固定。`commands.json` ではなくVSCode側に保存されるため、Gitに差分が出ない |
| 常駐コマンド | `npm run dev` のようなプロセスを起動・停止。停止時はプロセスグループごと終了するため、孫プロセスが残らない |
| 実行中の状態表示 | 経過時間と最終出力からの経過を毎秒更新。ツールチップに直近5行を表示 |
| ログへの導線 | 項目をクリックすると、実行中ならそのログ、停止中なら最後の実行ログが開く |
| 実行履歴 | 「履歴」ビューに実行結果を新しい順で表示。承認待ちが処理後に消えても、何を実行・拒否したか追える |
| 件数バッジ | アクティビティバーのアイコンと各ビューに、承認待ち・実行中の件数を表示 |
| 終了時の後始末 | VSCode終了時に実行中プロセスを全て停止し、終了を待ってからウィンドウを閉じる |
| シーケンス | 複数コマンドを順次実行。失敗した時点で打ち切り、その旨をログに記録 |
| ブランチ連動 | `branches` 指定で、特定ブランチにいるときだけ表示（例: 本番デプロイは `main` でのみ） |
| 実行前確認 | `confirm: true` で破壊的コマンドに確認ダイアログを挟む |
| ステータスバー | 実行中プロセス数を常時表示 |
| ログローテーション | 常駐コマンド対策に、既定で直近5000行のみ保持 |

## commands.json

```json
{
  "commands": [
    {
      "id": "dev",
      "label": "開発サーバー",
      "kind": "daemon",
      "command": "npm run dev"
    },
    {
      "id": "release",
      "label": "ビルドしてデプロイ",
      "kind": "sequence",
      "steps": ["npm run build", "npm test", "npm run deploy"],
      "confirm": true,
      "branches": ["main"]
    }
  ]
}
```

JSON Schemaが登録されているため、エディタ上で補完が効きます。全フィールドは [schemas/commands.schema.json](schemas/commands.schema.json) を参照してください。

## ログ形式

`logs/<id>.json`（概況）と `logs/<id>.log`（全文）に分かれています。要件段階では単一JSONにstdout全文を入れる案でしたが、常駐コマンドの出力をJSON文字列に押し込むと肥大化してAIがパースできなくなるため分離しました。

```json
{
  "schemaVersion": 1,
  "runId": "run-tests",
  "source": "request",
  "requestId": "run-tests",
  "label": "テストを実行",
  "kind": "oneshot",
  "command": "npm test",
  "cwd": ".",
  "status": "failed",
  "exitCode": 1,
  "startedAt": "2026-07-17T10:00:00.000Z",
  "endedAt": "2026-07-17T10:00:42.000Z",
  "durationMs": 42000,
  "logFile": ".vscode/ai-runner/logs/run-tests.log",
  "tail": ["...末尾50行..."]
}
```

`logs/index.json` に実行履歴が新しい順で最大200件記録されます。`commands.json` 由来の実行は `<id>_<timestamp>` として履歴が残るため、AIは index 経由で過去の失敗を辿れます。一方リクエスト由来の実行は、AIが結果の場所を事前に確定できることを優先し、`<requestId>` 固定にしています。

`logs/` と `requests/` は実行環境依存の生成物なので、`.vscode/ai-runner/.gitignore` で除外しています。

## 開発

```bash
npm install
npm run compile
node --test test/run.js   # 実行エンジンの結合テスト
```

F5（「拡張機能を起動」）で Extension Development Host が立ち上がります。

テストは `vscode` モジュールをスタブ化して、実行エンジンを素のNodeで走らせています。実際に子プロセスを起動し、ログファイルの内容・プロセスツリーの停止・ログローテーション・パス検証を検証します。
